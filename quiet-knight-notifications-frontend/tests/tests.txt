# Tests

## Test 1 - Open an invite, recover the same seat, and exchange moves [sanity]
Viewport: mobile (375x667)
Covers: Railway room creation, direct invite join, Redis-backed idempotent join credentials, initial Railway room read, Railway WebSocket live updates, move validation, board geometry
Description: Checks the actual second-phone workflow instead of just app startup.
Steps:
1. Actor A chooses Create live game and copies the invite. On Web Share capable phones, Share invite is primary and Copy invite remains available. Verify the native share receives the direct room URL, cancellation is quiet, and denial/unavailable API falls back to copy.
2. Actor B in a separate browser context opens that exact invite. Verify joining ends with a board, not a permanent Please wait screen.
3. Reload B using the same URL. Verify B recovers Black, not a spectator, while A remains White.
4. Verify both connection labels say Live and A sees Opponent or the friend’s Knight ID, not Seat open. A and B must report Opponent at the table; spectators do not count as present.
5. Leave A to the menu, choose Resume live game, then reload the home URL and resume again. Verify the same White seat and room; spectator-only rooms must not become a resume target. An expired remembered room clears only that pointer with a graceful message.
6. A plays e2-e4. B sees it without refresh and plays e7-e5. A sees e5 and plays g1-f3.
Expected: First viewport follows opponent strip, nearly full-width board, own strip, compact state and contextual action. Detailed material legend, history, exports and preferences are inside Table controls. Compact current-board material points are visible beside captured-piece rows in both normal and Zen modes. Captured-piece rows remain visible below the table actions in BOTH normal and Zen mode. Verify 390x844 and 360x800: no horizontal clipping, equal squares, close/Escape/backdrop behavior and accessible 44px controls. The sheet scrolls to diagnostics without scrolling the underlying board; closing restores normal scrolling. Both display the same room, 1. e4 e5 2. Nf3, Black to move, and correct owned seats. The honey-and-walnut board is square, has exactly 8 equal rows and columns, fills the mobile width without horizontal overflow, and shows complete ivory/ebony piece silhouettes. Captured rows are readable directly on the table in both normal and Zen mode. No coordinate labels return. A failed join returns an actionable error rather than leaving the UI locked indefinitely.

## Test 2 - Recover connection loss without accepting stale moves
Viewport: mobile (375x667)
Covers: offline detection, bounded Railway WebSocket reconnect, authoritative socket reconciliation, heartbeat timeout, retired-socket event guard, manual reconnect, spectator and turn guardrails, refresh and seat preservation, Android background return, exhausted-retry recovery, page freeze and BFCache restore
Description: Confirms recovery and permission boundaries on the real shared room.
Setup:
1. A creates a room; B joins as Black; C joins as spectator.
Steps:
1. A plays e2-e4 and attempts d2-d4 before B replies. C also attempts a move.
2. Disconnect A from the network. Verify its position remains visible and its label says Offline, not Live.
3. B plays e7-e5 while A is disconnected.
4. Restore A's network. Verify A returns to Live and shows e5 without a page reload.
5. A plays g1-f3, making Black next to move. Switch A to another app or lock the screen for at least two minutes. While A is away, play b8-c6 with B. A must pause hidden-page retry timers. B sees Opponent stepped away while A is hidden, then Opponent at the table on return. At most one quiet synthesized knock plays per arrival, none on initial hydration or within a 30-second reconnect burst. Return to A: it must open a fresh socket for the SAME room, retain White and show B’s latest move. Live appears only after that new socket snapshot. Repeat with screen off/on, browser back/forward cache restoration and page freeze/resume. Consecutive focus/pageshow/visibility events must not keep replacing the new connection. A late message or close from the old socket must not disturb it or overwrite newer state.
6. Exhaust A’s bounded connection attempts while foregrounded. Restore the network or background and return to A: a NEW bounded attempt sequence must begin automatically, even after Connection unavailable. Suppress messages on an open socket and confirm heartbeat timeout still triggers recovery.
7. Open Table controls, expand Preferences & diagnostics and Copy diagnostics. Verify the copied plain text has current frontend/backend builds, room/version, socket status, update age, retries/reason, page/PWA and offline status, with no seat tokens, join keys or credentials. If clipboard is denied the selectable report remains available.
8. Open A's Table controls, expand Preferences & diagnostics and choose Reconnect now. Verify it rejoins the same room and seat. B still sees the same game.
Expected: Out-of-turn and spectator moves never apply. Offline play is not submitted to a shared room. Live appears only after the Railway WebSocket delivers an authoritative room update. Repeated failed retries stop with Connection unavailable and a manual reconnect option rather than an infinite loop.

Change sound and haptics, leave to the menu, and choose Play Black while offline. Verify Black is at the bottom and the computer moves White.
