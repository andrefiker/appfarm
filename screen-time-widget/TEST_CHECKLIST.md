# Screen Time Widget 1.1.0 — phone release checklist

Automated execution is recorded in VERIFICATION.md. No attached physical adb device was available. Host-side Android tests do not establish launcher/OEM behavior.

1. Install the APK over v1.0.0 without uninstalling. Check version 1.1.0 and preserved exclusions/top-N/time style/explicit instant preference. Package and signing certificate must match.
2. Deny Usage access: app/widget show a clear grant/access message. Grant it (App info → Allow restricted settings if required), return to app and verify recovery. Revoke it while instant mode runs, then restore/reopen: uncertain continuity must not earn a break.
3. Turn Instant return updates on. Notification is low-importance/silent; no celebration notification. Phone off for 2 minutes, unlock: widget shows a short completed break, no milestone. Repeat for 10/20+ minutes: automatic quiet recognition. Merely wake the locked screen: no completed break.
4. Repeated unlock/screen off cycles: counts advance once per supported unlock and one break per completed interval. Refresh/open app repeatedly: no new message selection, no duplicate achievements.
5. Leave screen off across 23:00–07:00: sleep portion is excluded; a wholly sleeping interval gives no daytime achievement. Test custom minute boundaries. Last-daytime total may legitimately be zero while overnight portion is shown separately.
6. Reboot during an unfinished interval: after first unlock, prior open interval is discarded, widgets recover and no huge reboot reward appears. Reboot with instant mode off: worker schedules recover without an unwanted service.
7. Ordinary process termination (`adb shell am kill com.ghost.screentimewidget`, with service off/backgrounded): subsequent read reconstructs events and persistent settings/awards/challenge. Separately run `adb shell am force-stop com.ghost.screentimewidget`: automatic updates must stop until explicit app relaunch, then history recovers. These are different Android behaviors.
8. Change clock forward/back by 10+ minutes; no inflated open-interval award. Change time zone and cross midnight (restore automatic time afterward): new challenge/date appears and uncertain/full-day baseline eligibility resets. Sleep boundaries and day labels follow local time.
9. Resize widgets to 2×2, 4×2, 4×3, 4×4/taller on the actual launcher. Check clipping at large font scale, long-duration labels, dark/light/system themes and app-list scrolling. Small widgets intentionally omit secondary detail. Verify status timestamp and instant/frozen secondary clock.
10. Battery restricted vs unrestricted and Xiaomi/HyperOS background autostart disabled/enabled: note delays or service kills. Instant UI must accurately indicate whether listener is running. No per-second work/query polling.
11. Empty history: unavailable values/baseline, no invented comparison. After three full observed days and six daytime breaks, milestones adapt. Comparisons use historical data only up to equivalent local time; inspect sample count.
12. Daily challenge completes automatically, stays complete after restart and expires without guilt/streak loss. No reward needs app launch/claim. Humor max 3/day, 90-minute separation; sleep/estimated/stale returns generate none.
13. Airplane mode / no connectivity: all app/widget features work; APK has no INTERNET/ACCESS_NETWORK_STATE permission. Digital Wellbeing/notification shortcuts degrade gracefully if missing.
14. Keep prior APK and key as rollback artifacts. Android normally rejects a lower versionCode; source rollback should be rebuilt with a higher code and the same key. Never advise uninstalling as a data-preserving rollback.
