# Test checklist — Screen Time Widget 1.0.0

Build-time checks are recorded in `VERIFICATION.md`. Device tests below require a connected Android 9+ phone and manual permission grants. They were NOT performed when no adb device was present.

- [ ] Install: `adb install -r app/build/outputs/apk/debug/app-debug.apk`. Open with `adb shell am start -n com.ghost.screentimewidget/.MainActivity`. Grant usage access, notification, unrestricted battery, and OEM autostart.
- [ ] No permission: before granting, add widget; it shows **Grant usage access**, opens the app on tap, and does not crash. Revoke permission later and refresh; same result.
- [ ] Preview/widget: compare screen total and top apps just after refresh. Launcher/System UI excluded. Edit exclusions, switch 12/24 timestamp style and top-N; refresh and check both views. Widget tap opens app, refresh icon works, list scrolls at 4×2, taller size shows all rows. Check light appearance with system dark mode ON.
- [ ] Screen off/on: with instant mode ON, note the value, use power button to turn screen off for 60 seconds, unlock. Expected: elapsed grows only by actual screen-on seconds, not the 60-second sleep. Try immediately pressing refresh to check against historical events.
- [ ] Long foreground interval: use an app for two minutes, return and refresh; duration increases. Switch apps; no unexpected extra counting after screen-off.
- [ ] Periodic mode: turn instant OFF; silent notification disappears. Force refresh yields corrected totals; document that the clock can remain stale when process is dead. Turn ON to restore immediate updates.
- [ ] Reboot: `adb reboot`, unlock when the phone returns. Expected: today’s UsageEvents totals restored, settings preserved, enabled silent service returns, widget refreshes. Before first unlock it may show unlock-needed state. Firmware-dependent autostart must be enabled.
- [ ] Midnight: temporarily disable automatic date/time, manually change the clock to 23:59, keep the screen on through midnight. Expected: date and screen total reset; a foreground app is clamped at 00:00. Repeat with screen off; unlock and verify reset. Restore automatic date/time afterward. Clock jumps can produce historical discrepancies; test rollover behavior, not equivalence of pre-jump totals.
- [ ] Ordinary process death: with main activity backgrounded, `adb shell am kill com.ghost.screentimewidget` (may spare an active FGS). For a true debuggable-process kill: `adb shell run-as com.ghost.screentimewidget kill -9 $(adb shell pidof -s com.ghost.screentimewidget)`. Expect START_STICKY restart when Android permits; refresh re-derives totals and retains settings. Inspect `adb shell dumpsys activity services com.ghost.screentimewidget`.
- [ ] Force stop: `adb shell am force-stop com.ghost.screentimewidget`. Expected: service/notification stop, no automatic screen-event recovery while force-stopped. Reopen via launcher or `adb shell am start -n com.ghost.screentimewidget/.MainActivity`; totals/settings recover and service returns if enabled. A ticking stale widget while force-stopped is an Android limitation, not lost history.
- [ ] Update: install a higher-version APK signed by the included same debug key using `adb install -r`; settings and widget remain. Different keys cannot update the existing installation.
- [ ] Time zone: change time zone, refresh; midnight is recalculated and alarm rescheduled. Restore original zone.
- [ ] Offline: airplane mode; all views, usage, settings and widget work. External OEM guidance is optional and opens in the browser.
