# Tests

## Play vs Bots starts a fresh game [sanity]
Viewport: mobile (375x667)
Covers: mode launcher, isolated room creation, automatic bot seating, human seating, authoritative hand start
Description: A visitor can start playing immediately without entering the old shared global table.
Steps:
1. Open the Poker Table root URL.
2. Tap Play vs Bots.
3. Wait for room setup to complete.
Expected: A new room code is shown, the visitor is seated, three bot players occupy separate seats, and a real Hold’em hand starts with server-derived state.

## Multiplayer room supports two independent players
Viewport: desktop (1280x800)
Covers: multiplayer room creation, shareable room link, second-player seat claim, room isolation, private-state boundary
Description: Actor A can create a room and Actor B can join that exact room without affecting another room.
Steps:
1. Actor A opens the root URL and chooses Multiplayer.
2. Actor A copies the room invite.
3. Actor B opens the clean invite link in a separate browser identity and taps Take a Seat.
Expected: Both actors appear at the same table, a hand starts when two eligible players are seated, unrelated room codes remain independent, and neither actor receives the other player’s private card faces.

## Seated identity survives reload
Viewport: mobile (393x852)
Covers: device credential persistence, one-time WebSocket ticket renewal, seated reconnect, recipient-specific snapshot recovery
Description: Reloading a seated multiplayer player does not create a duplicate identity or lose the authoritative seat.
Steps:
1. Seat Actor A in a multiplayer room.
2. Reload the page completely.
3. Wait for the WebSocket to reconnect.
Expected: Actor A returns to the same room and same seat with the same device credential, receives a fresh connection ticket, and sees only Actor A’s private cards.

## Draw selection is explicit
Viewport: mobile (430x900)
Covers: queued Five-Card Draw variant, draw-card selection, stand-pat confirmation
Description: Five-Card Draw presents an unambiguous choice to keep all cards or replace selected cards.
Steps:
1. In an active room, queue Five-Card Draw between hands.
2. On the draw turn, select zero and then several cards.
Expected: The interface reads Keep all 5 or Replace N cards and only the selected local cards lift.

## Launcher and table remain mobile-contained after cache upgrade
Viewport: mobile (360x800)
Covers: stale PWA shell retirement, mode launcher, five-zone table layout, Hatchable-hosted static shell
Description: A browser carrying the older single-table shell upgrades to the room launcher without clipping controls or seats.
Steps:
1. Reload the root URL from a browser that previously used Poker Table.
2. Start either a bot or multiplayer room.
3. Reload once more after the service worker activates.
Expected: The launcher and room UI load from the new shell, all five seat zones fit without horizontal overflow at 360, 393, and 430 pixel widths, and authenticated game responses are never served from static cache.
