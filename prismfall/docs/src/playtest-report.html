The input was real: keyboard events, mouse moves and clicks, and a mocked standard gamepad. A heuristic AI bot played the runs; it reads the board through a read-only debug hook and plays through those same inputs. Everything below marked PASS was actually executed. Anything not executed is listed as an assumption under Known remaining issues. Nothing was tested on a Windows machine.

Known remaining issues & assumptions

  • Not tested on Windows: All testing ran on Linux in headless Chromium. Assumption: Edge/Chrome on Windows behave the same, since the game uses standard canvas, Web Audio and localStorage only. Fonts will differ (Segoe UI on Windows vs DejaVu in these screenshots).
  • .bat launcher: Not executed (no Windows here). It's a two-line script: start "" "%~dp0index.html". Assumption: it opens the default browser on Windows 10/11.
  • Prismfall.exe: Cross-compiled for Windows x64 (PE32+ GUI, icon embedded). The same Go source was run as a Linux build and verified to serve the game, answer heartbeats and exit cleanly when a second copy starts. The .exe itself was never run on Windows. It isn't code-signed, so SmartScreen may warn.
  • Separate saves: Browsers store progress per address, so the .bat/index.html (file://) and the .exe (http://127.0.0.1:47613) keep separate progress. This is documented in README.txt.
  • Audio: Verified programmatically: the engine starts on the first click or key, all 22 SFX and both music modes run with no errors, and the sequencer advances. Assumption: the mix sounds good. It was never listened to; a headless browser has no speakers.
  • Gamepad: Tested with a mocked standard-mapping pad (navigator.getGamepads override), not a physical controller. Assumption: Xbox and PlayStation pads using the standard mapping behave the same.
  • Frame rate: Measured in headless Chromium with software rendering. Assumption: a desktop GPU is at least as smooth. Not measured on your machine.
  • Fun: The first-60-seconds judgement is my own assessment from watching bot runs and screenshots. No human has played it yet. Balance values (gem rate, perk costs, Burst size) are first-pass estimates.
  • Bot skill: The bot never uses T-spins and plays at machine precision. T-spin scoring was verified with a scripted setup instead (T-spin double = 1200).
  • Missing SpriteCook art: All art is procedural placeholder art because SpriteCook wasn't connected. The full list of missing assets is in docs/ASSET_MANIFEST.md.
  • Browser Use: Not available. The playtest used Playwright + headless Chromium instead (real input events, real browser engine).
