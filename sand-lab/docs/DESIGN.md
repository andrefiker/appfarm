# Design decisions and visual QA

The owner's implementation brief delegates architecture and design decisions. The APK-first workflow is used without a new design approval round. Options considered: native Kotlin Canvas (single Android target, less reusable), WebGL (additional shader complexity), or dependency-free Canvas plus tiny native WebView (selected: existing AppFarm pattern, directly testable rules, identical browser/Android simulation).

The primary screen follows the generated portrait concept: dark navy background, mint SAND LAB accent, Worlds/settings header, dominant simulation canvas, compact Pause/Undo/Erase/Tools row, two rows of five materials, brush slider and speed. A code-native deterministic grid is an intentional deviation from the concept's illustrative texture: every visible particle represents a real cell. No concept screenshot or decorative bitmap is shipped as gameplay. Vector app icon depicts a flask containing sand and water. System fonts avoid a remote dependency.

Compared concept and browser captures directly with image inspection. Five checks: (1) header copy/hierarchy preserved; (2) canvas dominates and compact tools stay below it; (3) dark/mint palette and individual material colors retained, with subtle hot-material glow; (4) material labels remain legible at 360 px, all controls reachable; (5) spacing and border system consistent across panels and themes. Intentional changes: smaller swatches, inline action labels, code-native tool glyphs, finite interactive volcano instead of static elaborate illustration. Extra hint copy helps first use and fades on painting. No marketing surface or progression.

Browser screenshots: docs/qa. Tested 360×640, 390×844, 768×1024. Rendered captures were inspected; no horizontal overflow or clipped footer. Modal scrolling supports smaller screens. Native WindowInsets applies status/navigation/cutout padding. Emulator evidence is distinct from browser layout evidence; no physical-phone evidence is claimed.
